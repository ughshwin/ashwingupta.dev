# Section swarm audit

Thirteen section agents were launched with `gpt-6.1-sol`, reasoning effort `high`, in batches of three. Each had separate file ownership. The parent integrated their adapters, shared reference context, validation and tests. The shared-chrome agent reached its usage limit after implementing changes; the parent finished its outstanding review and verification.

| Section | Completion work |
| --- | --- |
| Overview | Feedback, menu accessibility, social labels and resume identity in content |
| About and achievements | Semantic biography copy; canonical dataset identity and shared count formatting |
| Experience | Stable historical role references; date-derived bounds; safe added-entry behavior |
| Impact | Canonical category order, project metrics, dataset labels and freshness copy |
| Featured | Narrow checked adapter; canonical project/employment references; authored badges |
| Projects | Canonical repository URLs; typed status semantics; source-controlled card order |
| Recommendations | Stable record IDs and historical company references; preserved quotes and layout |
| Stack | Readable technology schema; icon identities in content; presentation in renderer |
| Contact and current work | Canonical contact rows, feedback and active-project references |
| Articles | Derived display dates, URLs and titles; canonical descriptions and essay subject |
| Research | Checked narrative types and stages; canonical publication facts and badges |
| Case studies | Canonical names, resources and compatible metrics; clearer document keys |
| Shared chrome and layout studies | Shared routes/resources/wording; canonical identity; reused runtime feedback/count helpers |

The migration preserves current copy, markup, styles, ordering, private-repository behavior, recommendation/Impact alignment, sidebar CV placement, and email feedback. All protected page scripts/styles and eight HSBC Mermaid sources remain unchanged. Historical migration parity is checked against the original 68-route snapshot; intentional earlier layout-study title corrections remain the only permitted text differences.

Structured source validation covers all JSON references, cycles, stable IDs, project/section relationships, card types/stages, technology icons, status semantics, dates and publication provenance. The render integration test changes actual source records in each rendered section, verifies output across both editions, checks article metadata/RSS, then restores the exact original source bytes and production build.
